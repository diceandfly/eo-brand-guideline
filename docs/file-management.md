# 파일 관리 튜토리얼

이 사이트를 편집할 때 손대는 파일은 세 종류뿐입니다. 글은 `content/guide.en.md`(영어판)와 `content/guide.ko.md`(한국어판), 이미지는 `public/assets/`, 디자인 수치는 `src/styles/tokens.css`.

## 1. 실행

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:4321 을 엽니다. 두 언어판이 함께 빌드되어 `/en/…`, `/ko/…` 로 나뉘고, 목차 하단 EN | KR 로 전환합니다. 루트(/)는 마지막으로 보던 언어로 보냅니다. 콘텐츠 파일(`content/*.md`)을 저장하면 브라우저가 자동으로 새로고침됩니다(토큰·CSS 는 새로고침 없이 반영). 검색 컴포넌트(`Search.astro`)의 스크립트만은 dev 서버가 캐시하므로 수정 뒤 서버를 재시작해야 합니다. 파일을 저장하면 바로 반영됩니다. 정적 파일로 빌드하려면 `npm run build` (결과물은 `dist/`).

## 2. 폴더 구조

```
content/guide.en.md       ← 영어판. 모든 글과 이미지 배치 (문법은 파일 상단 주석)
content/guide.ko.md       ← 한국어판. 같은 문법
public/assets/<챕터>/<서브챕터>/ ← 이미지. 파일명 <주제 번호>-<이름>, guide.<lang>.md 의 ![이름] 과 1:1 대응
scripts/assets.mjs        ← 이미지 폴더 정리 (npm run assets)
public/fonts/             ← Founders Grotesk woff2 (저장소에 커밋되지 않음)
src/styles/tokens.css     ← 마진·거터·타이포·컬러·비율 토큰. 디자인 튜닝은 여기서만
src/styles/base.css       ← 토큰을 참조하는 레이아웃 CSS
src/styles/fonts.css      ← @font-face 선언 (파일명 매핑)
src/components/           ← Section / Figure / Swatch · SwatchVal / Sidebar / Search / Logo
src/layouts/Layout.astro  ← 페이지 셸 (목차 + 본문 + 모바일 드로어)
src/pages/                ← 라우팅. 건드릴 일 거의 없음
src/lib/guide.ts          ← guide.<lang>.md 파서
docs/                     ← 이 문서
```

## 3. 이미지 넣기

1. `guide.ko.md`(국문이 기준) 에서 `![construction]` 처럼 파일 이름만 씁니다.
2. 플레이스홀더 박스에 적힌 경로에 파일을 넣습니다: `public/assets/02-logo/01-symbol/03-construction.png`
   - 폴더는 `<챕터>/<서브챕터>` 2단이고, 파일명 앞 번호는 그 이미지가 속한 주제의 순서입니다. 주제는 목차에 보이는 항목 이름입니다(헤드, 헤드가 페이지 이름과 같으면 서브헤드). 그래서 탐색기에서 파일이 페이지 순서대로 정렬됩니다.
   - 번호 없이 이름만 붙여 넣어도(`construction.png`) 화면에 나오고, `npm run assets` 가 번호를 붙여 줍니다.
   - 확장자는 svg, png, jpg, jpeg, webp, gif, avif 중 아무거나. 같은 폴더에 같은 이름이 여럿이면 svg 가 우선합니다.
   - 사이트는 번호를 보지 않고 그 서브챕터 폴더 안에서 파일 이름으로 찾습니다. 그래서 파일 이름은 서브챕터 안에서 겹치지 않아야 하고, 다른 서브챕터와는 겹쳐도 됩니다.
   - 파일이 없는 동안은 넣을 경로가 적힌 플레이스홀더 박스로 표시되므로, 어떤 이미지가 비어 있는지 화면에서 바로 보입니다.
3. 프레임 비율(`--ratio-*` 토큰) 안에 넣는 방식은 `tokens.css` 의 `--img-fit` 으로 정합니다(cover = 꽉 채우고 잘림, contain = 전부 보임). 이미지를 클릭하면 확대 보기가 열리고, 아무 곳이나 클릭하거나 Esc 로 닫힙니다.

**폴더 정리 (`npm run assets`)**. 국문(`guide.ko.md`) 구조를 기준으로 서브챕터 폴더를 만들고, 파일명 앞 번호를 지금 주제 순서에 맞춰 바꾸고(번호가 없으면 붙이고), 비어 버린 옛 폴더를 지웁니다. 섹션 순서를 바꾸거나 이미지를 새로 넣은 뒤 한 번 실행하면 됩니다. 마지막에 페이지별 빠진 이미지 수와 어디에서도 쓰지 않는 파일 목록을 보여 줍니다(파일은 지우지 않음). 옮기기 전에 확인만 하려면 `npm run assets -- --dry`.

**이미지 가져오기 (`npm run import -- <서브챕터>`)**. 내보낸 이미지 폴더(기본: 다운로드/temp)에서 국문 가이드의 이미지 이름과 같은 파일을 찾아, 번호를 붙여 제자리에 복사합니다. 원본은 지우지 않습니다.

```
npm run import -- symbol            # 다운로드/temp 에서 Symbol 이미지 가져오기
npm run import -- symbol --dry      # 미리 보기 (복사 안 함)
npm run import -- typography ~/Desktop/export   # 다른 폴더에서
npm run import                      # 서브챕터 목록 보기
```

- 파일명 앞 접두어(마지막 `_` 까지, 예: `20261016 Finalization_`)와 앞 번호는 떼고, 공백은 `-` 로 바꿔 비교합니다.
- 같은 이름의 예전 파일은 새 파일로 바꿉니다. 그림이 같으면 건드리지 않습니다. 다시 내보내면 그림이 같아도 바이트가 달라질 수 있어 픽셀로 비교하고(macOS `sips`), 끝에 그림이 바뀐 이미지 이름을 보여 줍니다.
- 가이드에 자리가 없는 파일과 아직 비어 있는 자리를 끝에 알려 줍니다. 이름이 다른 파일은 추측해서 넣지 않습니다.
- `clearspace`, `dont-1` 처럼 여러 서브챕터에 같은 이름이 있으므로, 폴더 안에 서브챕터 이름의 하위 폴더(`temp/symbol/`, `temp/typography/` …)를 만들어 나눠 두면 섞이지 않습니다. 하위 폴더가 있으면 그 폴더에서만 가져옵니다.

파일명은 소문자와 하이픈만 씁니다. `brand/logo.svg` 는 콘텐츠 이미지가 아니라 목차 상단 로고이며 이 규칙과 별개입니다.

## 4. 폰트 넣기

`public/fonts/` 에 아래 파일명으로 woff2 를 넣습니다.

| 파일명 | 웨이트 |
|---|---|
| FoundersGrotesk-Light.woff2 | 300 |
| FoundersGrotesk-Regular.woff2 | 400 |
| FoundersGrotesk-Medium.woff2 | 500 |
| FoundersGroteskMono-Regular.woff2 | 400 (모노) |

파일명이 다르면 `src/styles/fonts.css` 의 경로만 고칩니다. 폰트 폴더는 `.gitignore` 에 들어 있어 저장소에 커밋되지 않습니다(유료 폰트 재배포 방지). 폰트가 없으면 시스템 산세리프로 폴백되니, 토큰 튜닝은 폰트를 넣은 뒤에 하세요.

## 5. 디자인 튜닝

`src/styles/tokens.css` 한 파일만 수정합니다. 항목마다 주석이 있습니다.

- 레이아웃: 목차 폭, 마진, 거터, 섹션 간격, 기본 섹션의 텍스트/이미지 컬럼 수
- 타이포: `--lh-unit`(기준 행간)과 레벨별 `m`(행간 배수), `p`(행간÷폰트), `ls`(자간), `w`(웨이트). 폰트 사이즈는 계산값이라 직접 쓰지 않습니다.
- 컬러: 브랜드 팔레트 7색은 그대로 두고, UI 시맨틱 토큰(`--bg`, `--fg`, `--accent` …)만 바꿉니다. 중간 톤은 `color-mix()` 퍼센트로 조절합니다.
- 비율: `--ratio-basic`, `--ratio-wide`, `--ratio-card`, `--ratio-swatch`

브레이크포인트(모바일 899px 이하)만 CSS 변수로 쓸 수 없어 `base.css` 의 `@media` 에 직접 적혀 있습니다.

## 6. 글 편집

문법은 `content/guide.en.md` 맨 위 주석에 전부 있습니다. 요약하면 `#` 챕터, `##` 서브챕터(=페이지), `###` 섹션 헤드, `####` 서브헤드, `![토큰]` 이미지, `[swatch]` 컬러 카드입니다. 섹션의 레이아웃은 이미지 개수로 자동 결정되고, 헤드 뒤 `{layout=… ratio=…}` 로 직접 지정할 수 있습니다.

따옴표는 곧은 따옴표(`"`, `'`)로 씁니다. 화면에는 앞뒤를 구분한 둥근 따옴표(“ ” ‘ ’)로 자동 변환되고, 단어 사이의 `'` 는 아포스트로피(’)가 됩니다. 검색은 곧은 따옴표 기준이라 검색창에 그대로 입력하면 됩니다.

국문 나열은 앞뒤를 띄운 가운뎃점(` · `)으로 씁니다. 점 앞 공백은 빌드할 때 줄바꿈 없는 공백으로 바뀌어, 줄이 점으로 시작하지 않습니다(점은 앞 단어에 붙고 뒤에서만 줄바꿈). 앞뒤를 띄운 슬래시(` / `, 예: `7L / 87.5%`)도 같은 방식으로 처리됩니다. 숫자 사이는 "2배 또는 3배"처럼 말로 풉니다.

guide.<lang>.md 의 빈 줄은 구조를 눈으로 구분하기 위한 약속입니다: 섹션(`###`) 앞 2줄, 서브챕터(`##`) 앞 3줄, 챕터(`#`) 앞 4줄, 헤드 바로 아래 첫 하위 헤드 앞과 문단 사이는 1줄. 화면 결과에는 영향이 없습니다.

## 7. 클로드코드로 편집할 때

프로젝트 루트의 `CLAUDE.md` 에 위 규칙이 요약되어 있어 클로드코드가 자동으로 읽습니다. "Logo 챕터에 Favicon 섹션 추가해 줘", "섹션 간격을 조금 줄여 줘" 처럼 말하면 각각 `guide.ko.md`(영문은 지시가 있을 때) 와 `tokens.css` 만 수정합니다.
